# Reproducibility package: "Keeping AI Data Agents from Overloading Shared Analytical Databases"

This folder holds the code, raw measurements and analysis scripts for every table and figure in the paper (PVLDB submission, Experiment, Analysis & Benchmark track). The experiment code here is the research prototype used for the paper; the packaged library in `src/` is a separate, maintained implementation of the same idea.

All data is synthetic and generated by `code/gen_db.py` from a fixed seed. No real company data is used.

## Layout
- `code/gen_db.py`: synthetic factory-analytics database (2M units, 12M process events; `--units 500000` for the scale check).
- `code/workload.py`: the agent query corpus (12 benign templates x 12, 13 mutated fault templates x 6 = 222 queries) and the dashboard queries.
- `code/guard.py`, `code/pg_guard.py`: QueryGuard (G1 static rules, G2 largest-cardinality check, G3 runtime/row budget, G4 session budget) with DuckDB and PostgreSQL adapters.
- `code/measure.py`, `code/measure_pg.py`: E1, isolated ground-truth labels.
- `code/interfere.py`, `code/interfere_pg.py`: E2, dashboard interference.
- `code/loop.py`, `code/loop_pg.py`: E3, repair loops.
- `code/e4_predictors.py`: template-held-out detection with learned baselines (Table "Template-held-out detection").
- `code/analyze.py`, `code/analyze_pg.py`, `code/analyze_runs.py`, `code/stats.py`, `code/fig_engines5.py`: tables, confidence intervals, significance tests and figures.
- `results/`: raw measurements (`*.json.gz`) and summaries for the runs reported in the paper.
- `results/earlier_env/`: an earlier three-run measurement (DuckDB 1.5.6, another VM of the same size) discussed in the paper's limitations.

## Environment used for the paper
4 vCPU, 15 GB RAM cloud VM; Python 3.11+; DuckDB 2.0.0 (4 threads); PostgreSQL 16 on port 5433 with `shared_buffers=2GB`, `work_mem=64MB`, `max_parallel_workers_per_gather=2`.


## Recompute the paper's numbers from the included raw data (minutes)
```bash
cd results && gunzip -k *.json.gz && cd ../code
mkdir -p ../results/an_duck
python3 analyze.py --e1 ../results/e1_ground_truth.json --e1-small ../results/e1_ground_truth_small.json --out ../results/an_duck
python3 analyze_pg.py --pg ../results/e1_pg_ground_truth.json --duck ../results/e1_ground_truth.json --out ../results/summary_pg_e1.json
python3 e4_predictors.py ../results/e1_ground_truth.json ../results/e1_pg_ground_truth.json ../results/e4_heldout.json
python3 stats.py ../results ../results/stats_both.json     # Tables 3-4: means, 95% CIs, Welch and Mann-Whitney tests
python3 fig_engines5.py ../results/stats_both.json ../results
python3 fig_extra.py ../results ../results        # threshold-sweep and repair-loop figures
```

## Re-run the experiments from scratch (about 6 hours on 4 cores)
```bash
cd code
export DB_DIR=/path/with/10GB/free
bash run_all.sh          # DuckDB: build DB, E1, scale check, E2 (original configs), E3
bash run_duckdb_v2.sh    # DuckDB E2/E3 with all eight configurations per session, seeds 11-15 / 21-25
bash run_extra.sh        # extra DuckDB runs of dashboard-only, G2-only and G3-only
# PostgreSQL: create database qg on port 5433, then
python3 pg_load.py --src $DB_DIR/analytics.duckdb
bash run_pg.sh           # E1, E2 (seeds 11-15) and E3 (seeds 21-25) on PostgreSQL
```
Run every configuration for an engine in one session: the paper reports each engine relative to the dashboard-only baseline measured in the same session, because absolute latency varies between machines and software versions.

Calibrated G2 thresholds: 5,793,600 estimated rows (DuckDB) and 2,000,000 (PostgreSQL), both chosen on the even half of E1 by `analyze.py` / `analyze_pg.py`.
